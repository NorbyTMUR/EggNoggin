Setting up an ArduPilot simulation on Windows

Jan. 20, 2026

Why SITL?

Software In The Loop (SITL) testing is used to test software before it goes onto a real piece of hardware. This testing prevents damage to physical objects and narrows down the potential causes of an unintended behavior to issues in the code. Before setting up an SITL system, I spent a lot of time writing code for my remote-controlled plane without being able to guarantee that my code wouldn’t cause the plane to crash. I don’t need help crashing my plane.

                           

The open-source software ArduPilot is one of the most reliable autopilots for remote-control vehicles. It is used by researchers, hobbyists, and even some militaries. Their documentation, although it provides a setup guide, doesn’t make it clear how SITL runs on a device, which is why the order of the setup steps is vital. They also don’t provide a series of steps that consistently runs SITL. This post provides a brief overview on how ArduPilot SITL runs on the Windows operating system, which it wasn’t designed for.  

The Downloads (and why)

  1. Cygwin: https://www.cygwin.com/install.html

Cygwin provides POSIX compatibility with Windows. It allows programs to be run on the Windows operating system without changing the program’s code. Windows and Linux have different management of hardware resources, so running the ArduPilot build system, waf, doesn’t work otherwise. Cygwin also provides a Linux terminal on the Windows Start Menu, called the “Cygwin64 Terminal”, to run commands from.

  1. MavProxy: http://firmware.ardupilot.org/Tools/MAVProxy/. MavProxy is a Ground Control Station and allows a drone to be remotely controlled, from the ground. A simulated plane can be controlled using text in the MavProxy command line interface. If you write a new mode of flight into the ArduPlane code, you can switch to that mode by calling it in MavProxy.        

        3. Clone the ArduPlane source code from GitHub locally: The URL for the ArduPilot code is: https://github.com/ArduPilot/ardupilot.git.  In order to build SITL, ArduPilot needs to be downloaded to a path on your computer.

  1. SilentWings: an industry-standard drone and glider simulator that allows for highly detailed inputs for wind conditions. It could simulate a different condition for every meter of altitude.

With everything assembled, we can now simulate a plane running on ArduPilot code, and control it in real time!

Procedure for Simulations

  1. Open a Cygwin terminal, and then use the command cd ./<path>/ to navigate to the location of your ArduPilot code. Then run the commands (in order):
  1. ./waf configure –board sitl: this selects the target, in this case SITL. On a normal flight, ArduPilot takes in many inputs from sensors
  2. ./waf plane : configures the ArduPilot code for the desired firmware, a plane’s flight controller

Waf is used by ArduPilot to include or exclude features based on the target (a plane running on SITL), and then builds an executable of ArduPilot for the simulation.

When I’m flying a real plane, I can see the cockpit sensors to make decisions; I use the throttle, ailerons, and rudders to control the plane. When a plane is controlled with an autopilot, the flight controller is running ArduPilot software. The software takes in sensor readings to make decisions, and uses servos to control the plane’s ailerons and rudder.

During SITL, SilentWings (rather than the plane’s instruments) provides ArduPilot with the flight data; wind speed, GPS position, gyro data, accelerometer data, all with realistic noise. ArduPilot then outputs what the actuators should do. Waf configures ArduPlane to accept simulation data, which comes with different drivers than taking data directly from sensors. The ArduPilot software is now in its own kind of VR headset, taking data from simulated sensors and controlling simulated actuators.

  1. Open SilentWings and set the desired location and weather conditions.

  1. Start running the SITL executable with the command: build/sitl/bin/arduplane –model silentwings –home <latitude>,<longitude>,<altitude>,<yaw>

The command takes in the 3D position of the plane in the simulation in order to start running the software-in-the loop code. The command is telling the SITL instance to open on the port defined by the ArduPlane executable on your computer. It also indicates that an instance of SilentWings is already running. All of these steps are described in the output message below:

ArduPlane is the application that is opening up the SITL connection. The terminal says “waiting for connection” because  ArduPlane waits for a connection (called a handshake) before transmitting all of its information. The handshake is a packet of information: an initial packet and an acknowledgment packet that the connected application needs to send back. To ensure a secure connection, they chose to use a TCP connection protocol to the Ground Control Station (MavProxy).

Using the secure, connection-oriented TCP protocol makes sense, because a connection needs to be maintained as long as the simulation is running.

  1. Once you see that SilentWings is “waiting for a connection”, open MavProxy and connect on TCP Port 5760.

Once a connection is established, more ports, like Port 5762 and 5763, are opened by ArduPlane. Those connections are opened so that more ground control stations and flight dynamics simulators could run “in the loop” as well. In Practice

By changing the mode to the ArduPlane mode “CIRCLE”, from the MavProxy terminal, the plane can be made to circle in place. It can also fly to waypoints added by the user, and provides a visual of the path it’s taken, the whole time. Even though it’s just being controlled in a simulation right now, this is the exact same experience as flying a plane in real life, through MavProxy. Once set up, MavProxy makes it easy and intuitive to control a real remote-control plane, almost like a video game.

Summary

 ArduPilot is launched to accept inputs from simulation drivers rather than sensors, so that it reacts realistically to a simulated environment. To simulate weather conditions and command the plane from the ground, other applications like MavProxy and SilentWings are connected to ArduPlane software. SITL is a way of “blinding” the ArduPilot software and convincing it that it is attached to a real plane. This robust virtual system is used to test software for RC planes, keeping countless remote-control planes out of trouble, and with the results of SITL simulations even being published in journals.
